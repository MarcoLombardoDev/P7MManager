# Third-party licences

P7M Manager is licensed **AGPL-3.0-or-later** (see [LICENSE](LICENSE)), with a
commercial licence available separately (see
[COMMERCIAL-LICENSE.md](COMMERCIAL-LICENSE.md)). That covers the code in this
repository. It does not cover the code P7M Manager is built on, and a
downloadable release is mostly that other code: a Linux build contains 217
native binaries and not one of them was written for P7M Manager. P7M Manager's
own code travels through them as Python bytecode.

This file is the inventory of what those binaries are and what licenses them.

## Almost all of it is Qt, and that is the part that matters

P7M Manager declares **one** runtime dependency. The engine under
[`p7mmanager/core/`](p7mmanager/core/) — the ASN.1 reader, the CMS parser, the
X.509 decoder — is written against the standard library and pulls in nothing,
which was a deliberate choice and is the reason this document is short.

What it does pull in is **PySide6**, and Qt is not BSD or MIT. It is
**LGPL-3.0**, and LGPL-3.0 asks more of a redistributor than any other licence
in this bundle:

| | |
|---|---|
| **§4** | the licence text must **accompany the object code** — not be available on request, not be linked to |
| **not self-contained** | LGPL-3.0 is a set of *additional permissions* on top of GPL-3.0, so shipping it alone ships half a licence |
| **§4(d), §4(e)** | the recipient must be able to **relink** against a modified Qt |

Those are the obligations a commercial licensee inherits, and
[COMMERCIAL-LICENSE.md](COMMERCIAL-LICENSE.md) is written on the assumption
they are met.

## How this was produced

The authoritative inventory is **not this file**. It is the one inside the
archive you downloaded, at `licenses/THIRD-PARTY-LICENSES-<platform>.md`,
generated by [`tools/licence_inventory.py`](tools/licence_inventory.py) on the
runner that built that archive — the only machine whose answer is your
download's own. PyInstaller collects whatever the build machine's linker
resolved, so the contents change when the runner image changes, not when
somebody edits this repository.

Every entry traces to a machine-readable source:

- **Python packages** — the top-level package a binary sits under names its own
  distribution, and that distribution's installed metadata states its licence.
- **Libraries collected from the Linux build machine** — the owning package
  from `dpkg-query`, and that package's `debian/copyright`.
- **Libraries the platform supplies** (the Windows CRT, the OpenSSL inside
  python.org's builds) — identified by name, since no package manager owns
  them.

Two traps in that lookup are worth stating, because both produce wrong answers
and both are handled in the script rather than papered over.

A `debian/copyright` file enumerates every licence appearing anywhere in the
*source* package, test fixtures and build scripts included. Reporting that
union is alarmist nonsense — it makes GLib look like it carries a GPL-2+ term.
What governs a shipped shared library is the licence of that library's own
sources: the stanza whose `Files:` pattern covers them.

And even the `Files: *` stanza is wrong when one source package builds several
libraries under different terms. util-linux's default stanza says GPL-2+, while
`libblkid` and `libmount`, which these builds do ship, are LGPL-2.1+ in their
own stanzas and `libuuid` is BSD-3-clause. Taking the default would have
published three wrong answers that looked authoritative. Those cases are in the
script's `REVIEWED` table, each with the stanza that was read.

Anything the script cannot resolve is reported as **unresolved** rather than
guessed at. These are statements about what the declared metadata and the build
machine's own records say, current as at the version of this document, and are
**not a legal opinion**.

## What P7M Manager depends on directly

| Package | Licence (from its metadata) | What it is for |
|---|---|---|
| **PySide6** | `LGPL-3.0-only OR GPL-2.0-only OR GPL-3.0-only` | the interface, and nothing else |

`PySide6` is a metapackage: installing it brings **PySide6-Essentials**,
**PySide6-Addons** and **shiboken6**, each declaring that same expression. **PyInstaller**
(`GPL-2.0-or-later WITH Bootloader-exception`) builds the executable.

There is no third-party ASN.1, CMS, X.509 or cryptography package in this list,
and that is the point: a signature-reading tool that pulled in a copyleft crypto
stack could not be offered under a commercial licence at all.

## The components that actually constrain redistribution

| Component | Licence | What it actually requires |
|---|---|---|
| **Qt 6**, via PySide6 — 105 binaries | `LGPL-3.0` | The text with the object code, GPL-3.0 alongside it, and the recipient able to relink. See above. |
| ICU, vendored inside the PySide6 wheel | `Unicode-3.0` | Reproduce the notice. Permissive. |
| the 22 LGPL system libraries a Linux build collects | `LGPL-2.0/2.1` | A copy of the licence with the object code, and the ability to relink. |
| CPython, frozen into the bundle | `PSF-2.0` | Retain the notice. Nothing further. |
| PyInstaller's bootloader | `GPL-2.0-or-later WITH Bootloader-exception` | Nothing: the exception exists precisely so a frozen program keeps its own licence. |

Everything else is MIT, BSD or Zlib and asks only that the notice travels with
the binary — which is what `licenses/` inside the archive is for.

**Relinking, concretely.** These are folder builds: every collected library is
an ordinary file inside the unpacked archive, so replacing one with a modified
build of the same library is overwriting a file. Nothing is statically linked
into the executable except PyInstaller's own bootloader, which carries the
exception that permits exactly that.

## What was deliberately removed

The standard library's optional `readline` extension links **libreadline**,
GPL-3.0-or-later with **no linking exception** — the one licence in reach that
would reach P7M Manager's own code, and the one a commercial licence could not
survive. P7M Manager is a windowed program that never reads a line from an
interactive prompt, so it is excluded in
[`p7mmanager.spec`](p7mmanager.spec) together with `rlcompleter`, which imports
`readline` and exists for nothing else. Every product in this family excludes
the same pair.

## Licence texts travel with the build

`licenses/` inside every archive holds the terms of everything in it:

- `P7MManager-LICENSE.txt` — this program's own AGPL;
- `python/PySide6/`, `python/PySide6_Essentials/`, `python/PySide6_Addons/`,
  `python/shiboken6/` — **LGPL-3.0 and GPL-3.0 in each**, supplied from
  [`licenses/`](licenses) in this repository because the PySide6 wheels declare
  LGPL-3.0 in their metadata and then ship no licence file at all;
- `cpython/Python-LICENSE.txt` — the interpreter and standard library, which
  are not a wheel and so have no metadata to read;
- `python/pyinstaller/COPYING.txt` — the bootloader's own terms, which *is*
  shipped;
- on Linux, the build machine's `debian/copyright` record for every system
  library PyInstaller collected.

[`tools/collect_licences.py`](tools/collect_licences.py) assembles it, and
[`tools/licence_inventory.py`](tools/licence_inventory.py) is run against the
tree about to be packaged with `--licences`, so a distribution that puts a
binary in the bundle and no notice beside it fails the release job rather than
shipping.

**Before 1.1.0 an archive carried P7M Manager's own LICENSE,
COMMERCIAL-LICENSE.md, README and CHANGELOG — and not one line of Qt's.**

## Full inventory

The per-binary table lives in the archive, not here:
`licenses/THIRD-PARTY-LICENSES-windows-x64.md`, `-macos-arm64.md` or
`-linux-x64.md`, depending on which one you downloaded. Each row names the
evidence it rests on so it can be re-checked, and rows the script could not
attribute are printed as **unresolved** rather than guessed at.

For the shape of it: a Linux build contains 217 native binaries — 108 from
wheels (105 of them Qt), 86 from the build machine, 23 CPython extension
modules.

## Build-time tools

**PyInstaller** produces the executable and its bootloader is shipped, under
the exception that permits it, so its `COPYING.txt` travels in `licenses/`
like any shipped component's. **pytest**, **ruff** and **Pillow** run on a
developer's machine and on CI and are in no archive, so their terms are not
reproduced in one.

## Known gaps

**The tables cover native binaries only.** Python code frozen into the bundle
as bytecode is not in them, and that is where a copyleft licence is most likely
to hide: a pure-Python package has no `.so` for the inventory to find. What
covers that here is the dependency table above — one package — plus the fact
that `licenses/` collects a notice per *distribution* rather than per binary.

**This file describes the source, not a specific build.** The counts above come
from one Linux build; the copy inside your archive is the one that describes
yours.

## Reproducing this

```
pip install . pyinstaller
pyinstaller --noconfirm --clean p7mmanager.spec
python tools/collect_licences.py build/licenses
python tools/licence_inventory.py --bundle linux=build/P7MManager \
    --licences build/licenses --markdown inventory.md
```

Exit code 2 means the report was written and some rows in it need a human.
