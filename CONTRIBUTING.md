# Contributing to P7M Manager

Bug reports, containers this tool cannot read, and patches are all welcome. A container
that fails to parse is the single most useful thing you can send — see
[Reporting bugs](#reporting-bugs) before attaching one.

## Ground rules

- **Be accurate about what the tool checks.** P7M Manager verifies integrity and, for RSA,
  the signature itself. It has no trust list, no revocation check and no timestamp
  validation. A change that makes the interface, the reports or the documentation sound
  like a legal validation will not be merged, however convenient the wording.
- **English in the code, both languages in the interface.** Source, comments and commit
  messages are in English; every user-visible phrase goes through `tr()` and gets an
  Italian in `p7mmanager/i18n.py`. A test fails if it does not.
- **No Qt in the engine.** Nothing under `p7mmanager/core/` may import PySide6. A test
  fails if it does.
- **No new runtime dependency without a reason that survives §11 of
  [COMMERCIAL-LICENSE.md](COMMERCIAL-LICENSE.md).** The engine's lack of dependencies is
  deliberate: a copyleft library underneath the parser would limit what a redistributor
  actually receives.

## Getting set up

```bash
git clone https://github.com/MarcoLombardoDev/P7MManager.git
cd P7MManager
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
python -m p7mmanager               # the window
python -m p7mmanager --cli --help  # the console tool
```

The test fixtures are signed by the `openssl` binary at collection time. Without it, the
CMS tests skip and the rest still run — but do not send a parser change validated only by
skipped tests.

## Before you write code

Read [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). It says which layer owns what, and why
the ASN.1 reader is in this repository rather than taken from a library.

For anything larger than a bug fix, open an issue first. A patch that arrives with no
prior discussion may be turned down on grounds that have nothing to do with its quality.

### Adding things

- **A new payload type** — extend `p7mmanager/core/payload.py` with its magic bytes, give
  it a label, add the label to `i18n.py`, and add a case to `tests/test_payload.py`.
- **A new attribute or extension to report** — the OID goes in `core/oids.py`, the reading
  of it in `core/cms.py` or `core/x509.py`, and the display in `ui/details.py`.
- **A new signature algorithm** — `core/verify.py`. Report what you cannot verify rather
  than returning a bare `False`: "not verified by this tool" and "does not match" are
  different answers, and users act on them differently.
- **A new interface string** — `tr("...")` at the call site, Italian in `i18n.py`.

## Style

`ruff` is the arbiter; line length 100, target Python 3.10:

```bash
ruff check .
```

Docstrings explain **why**, not what the next line already says. Comments earn their place
by recording a decision or a trap, not by narrating the code.

## Tests

```bash
pytest                             # everything
pytest tests/test_cms.py -v        # one file
```

A patch comes with tests. Parser changes come with a fixture that reproduces the container
in question — generated by `tests/conftest.py`, not committed as a blob, unless the file
cannot be reproduced any other way and carries nothing confidential.

## Commits and pull requests

Commit messages: a short imperative subject, then the reasoning if the change is not
obvious. See `CLAUDE.md` for this repository's branch and attribution rules.

## Reporting bugs

Open an [issue](https://github.com/MarcoLombardoDev/P7MManager/issues) with the version,
your operating system and Python version, and what happened.

**Before attaching a .p7m file**, remember that it contains the signed document and the
signer's certificate — a real name, often a fiscal code, sometimes a contract. Prefer a
container you have signed yourself for the purpose. If only the real file reproduces the
problem, say so in the issue and send it by
[email](mailto:marco.lombardo@gmail.com?subject=P7M%20Manager%20bug) instead of attaching
it to a public issue.
